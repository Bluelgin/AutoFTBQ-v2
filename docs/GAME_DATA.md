# 游戏数据覆盖（alpha.10）

生产工具为 `inspect_game_data`。结果区分 ok、not_found、unsupported、unavailable、error、stale_version、permission_denied 和 too_large；客户端与服务端来源分别标记，不把未知信息当作不存在。

| 查询 | 来源与范围 | 限制 |
| --- | --- | --- |
| capabilities | 当前实现覆盖清单 | 不代表模组玩法完整覆盖 |
| registry_page | 客户端注册的物品、方块、实体、流体、配方类型 | 按 ID 搜索、namespace 过滤、分页；不判断内容完成度 |
| item_evidence | 精确 ID、名称、标签、基础模型或自定义渲染状态 | 可获取性与开发完成度保留 unknown |
| recipes | 客户端已加载配方的输入、输出与类型 | 每页最多扫描 200 个配方；必须跟随 has_more；材料候选有截断；不能覆盖独立机器系统 |
| server_resource | 服务端战利品表、进度目录分页与指定 ID 的 JSON | 省略 id 先发现资源，再按真实 ID 读取；需要编辑权限，单资源最多 64KB；不覆盖脚本运行时修改 |

注册表和配方分页可携带 data_version；配方或标签重载时失效。服务器资源返回内容指纹。inspect_game_data 不复用旧请求缓存，避免把旧数据当作新世界事实。

未完成覆盖：服务端有效战利品运行时序列化、交易、Boss 召唤规则、各机器/研究系统专用适配器、整合包禁用规则、完整的获取关系图和机器可验收的玩法覆盖清单。需按 CYL 具体模组逐项适配；不能宣称已实现全部模组数据覆盖。

验收：查询不存在 ID 与未知来源物品；分页读取超过 100 项注册表；空配方页仍继续翻页；重载数据后拒绝旧分页版本；无编辑权限拒绝服务端资源查询；确认条件掉落不被称作必定掉落。Java 构建和 Python 单元测试不能替代真实客户端/独立服务器验收。
