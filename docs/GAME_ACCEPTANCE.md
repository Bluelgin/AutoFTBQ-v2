# 游戏内 Agent 验收清单

适用基线：Minecraft 1.20.1、Forge 47.2.19、FTB Quests 2001.4.22、Java 17。

## 测试前准备

1. 复制一份测试世界和任务书，不在正式存档上首次验证。
2. 启动 AutoFTBQ Studio，并确认模型配置可用。
3. 将 `game-mod/build/libs/autoftbq-agent-forge-1.20.1-0.1.0-alpha.9.jar` 与匹配版本的 Architectury、FTB Library、FTB Teams、FTB Quests 放入客户端和服务端；禁用旧版 AutoFTBQ Agent JAR，避免重复加载。客户端与服务端必须使用同一 JAR。
4. 使用有 FTB Quests 编辑权限的账号进入测试世界；另准备一个无编辑权限账号用于拒绝测试。

## 必测流程

| 场景 | 操作 | 预期结果 |
| --- | --- | --- |
| 原生面板 | 进入 FTBQ 编辑模式，点击 `Agent` 或按 `G` | 面板在原生任务画面右侧展开，不切换到独立窗口；关闭后画布可正常操作 |
| 连接 | 展开面板并切换章节、查看任务、多选任务 | 上下文自动更新，无需手工同步；无令牌或端口信息泄露 |
| 只读查询 | 询问选中任务详情、物品 ID 和配方 | 回答来自实时游戏查询；不存在的 ID 不得被当成有效物品 |
| 批量图标 | 多选至少 10 个 Boss 任务并要求按现有物品奖励校准图标 | Agent 使用批量查询，进度显示查询计数，不逐任务往返；没有可靠奖励时明确不猜测 |
| 多轮对话 | 在游戏和 Studio 分别连续追问，再浏览上一条/下一条 | 两端共享同一项目会话；重启 Studio 后历史仍可浏览和复制 |
| 取消 | 在模型处理时取消 | 状态变为已取消，迟到结果不覆盖界面 |
| 重复发送 | 第一项请求运行时再次发送 | 明确提示已有请求，可等待或取消；第二项不会静默排队 |
| Studio 中断 | 请求运行时关闭并重启 Studio | 旧工作记录标记为已中断，不会永久显示处理中；可重新发送 |
| 自动写入 | 请求创建一个含正文的任务并修改现有任务 | 显示修改记录，并自动作为一个服务器事务写入；不再要求玩家二次确认 |
| 权限拒绝 | 无编辑权限账号请求修改 | Studio 或服务端明确拒绝，任务书不变化，Agent 不得声称已写入 |
| revision 冲突 | Agent 生成事务期间手动修改任务书 | 提示冲突，不应用任何事务操作 |
| 核心写入 | 一次提案创建章节/任务、正文、依赖、物品/勾选/经验条件、物品/经验奖励 | 全部一次提交，重新打开任务书后仍存在 |
| 界面保持 | 在缩放、平移并多选任务后请求一次写入 | 原地刷新，仍停留在原章节和相同缩放/画布位置，仍存在的选中任务保持选中，Agent 面板保持展开 |
| 原子回滚 | 在批次末尾放入一个无效对象或无效物品 ID | 整批失败，前面的对象也不残留 |
| 撤销 | 成功写入后立即点“撤销写入” | 恢复写入前状态并保存、同步 |
| 撤销冲突 | 成功写入后手动改任务书，再点撤销 | 拒绝撤销，保留用户后续修改 |
| 断线恢复 | 写入回报阶段暂时关闭/阻断 Studio，随后恢复 | 游戏不重复创建对象；Studio 最终收到相同应用结果 |
| 游戏到工作台 | 在游戏内原生编辑任务书，等待约 10 秒，再点 Studio 的“在工作台编辑游戏任务书” | Studio 载入同一本任务书以及未知字段和 Mod 自定义任务/奖励原始数据 |
| 工作台到游戏 | 在 Studio 修改已载入的游戏任务书并点“同步到游戏” | 游戏自动应用差异、刷新原生 FTBQ 界面，并提供一次撤回 |
| 双端冲突 | Studio 载入后先在游戏内修改，再从 Studio 同步旧副本 | 同步被拒绝并要求重新载入，不覆盖游戏内较新的修改 |
| 切换世界 | 在两个世界间切换，其中任务书 revision 恰好相同 | 每个世界对应独立共享项目，Studio 看到正确任务书，不沿用另一世界快照 |
| 长文本 | 请求超过一屏的分析 | 可滚动、复制，按钮不遮挡正文 |

## 操作覆盖

- 章节：创建、标题、副标题、物品图标。
- 任务：创建、标题、副标题、正文段落、物品图标、坐标更新。
- 关系：添加任务依赖，并拒绝自依赖或无效依赖。
- 条件：物品、手动勾选、经验点。
- 奖励：物品、经验点、经验等级。
- Studio 原样同步：章节组、奖励表、章节、任务、任务条件、奖励和未知原始字段。
- 明确不开放：任意游戏命令和绕过服务端权限、revision 校验或事务回滚的写入。

## 失败处理

- 不要在“服务器事务结果未知”时手工重复创建相同任务；客户端会以同一提案 ID 自动重试。
- 若 revision 冲突，在 Studio 重新载入游戏任务书，或让 Agent 基于最新任务书重新生成事务。
- 若回滚失败，立即停止编辑，保留 `logs/latest.log` 和测试世界副本，不要覆盖备份。
- 验收完成前，发布说明必须保留“仅在备份世界测试”的 Alpha 警告。
