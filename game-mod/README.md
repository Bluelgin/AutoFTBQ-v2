# AutoFTBQ Agent Mod

AutoFTBQ Studio 的游戏内前端。当前原型支持 Minecraft 1.20.1、Forge 和 FTB Quests 2001.4.22。

当前开发版在 alpha.14 的暂停/继续、权限同步与实时提交基础上，进一步整理了游戏内 Agent UX：Agent 面板现在采用渐进式操作按钮、自动上下文 + 可选固定上下文，并允许在 FTBQ 编辑权限仍在同步时以只读方式打开。布局画板也统一接入语言文件并收起低频工具。

alpha.14 增加暂停/继续，并修复整本同步后编辑权限丢失。需要同时更新 Studio 后端以启用工具步骤实时提交；旧版后端没有暂停接口。暂停不丢弃已提交修改，撤销仍仅支持最近一批。

alpha.12 修复批内对象索引及同步时面板消失，并包含 alpha.11 的 SNBT 与回滚修复。客户端/服务端须同时更新。开发时运行 `gradlew.bat build strictSnbtSmoke questIndexSmoke sketchSmoke` 可验证真实 Mojang 解析器、FTBQ 对象索引、画板导出和面板状态；此烟测不替代游戏内撤销与故障回滚验收。

## 开发环境

- Java 17（必须；不要使用 Java 21 启动当前 Gradle 8.1.1 构建）
- Minecraft 1.20.1
- Forge 47.2.19

## 构建

```powershell
cd game-mod
.\gradlew.bat build
```

输出位于 `game-mod/build/libs`。

## 当前操作

1. 先启动 AutoFTBQ Studio。
2. 在安装了 FTB Quests 的 1.20.1 Forge 客户端中安装本 Mod。
3. 进入世界并打开 FTBQ。即使编辑权限尚未同步，也可以先打开 Agent 查看状态与历史；真正写入仍要求 FTBQ 编辑权限。
4. 在 FTBQ 右上角点击 `Agent`，或按 `G` 打开/收起右侧 Agent 面板。
5. Agent 会自动跟随当前 FTBQ 视图、当前章节和正在查看的任务。需要额外固定范围时，可在 Agent 展开状态下 `Alt + 左键` 点击任务或章节；固定项会以绿色描边显示。
6. 直接输入自然语言要求并发送。默认只显示当前阶段需要的动作：空闲时主要是“发送 / 更多”，执行中出现“取消 / 暂停继续”，服务器成功写入后出现“撤销”。
7. “更多”用于低频操作，包括布局画板、历史前后浏览、复制回答和清空固定上下文。
8. 当前 Agent 模式会在安全检查通过后自动应用事务，并在面板顶部明确标注“自动应用修改 · 完成后可撤销”。
9. Studio 连接状态下可点击“在工作台编辑游戏任务书”，编辑后点击“同步到游戏”；游戏端会自动领取并应用工作台事务。

Agent 面板是 FTBQ `QuestScreen` 的原生 FTB Library 子面板，不会再打开一套独立任务书编辑器。Studio 只负责模型、索引、安全策略和 Agent 后端。它可以读取当前视图与固定上下文，批量搜索或校验游戏内实时物品、方块和实体注册表，并按精确物品 ID 查询当前世界加载的配方。长回答可以滚轮浏览或复制。

Agent 会生成易读的结构化事务并自动应用；应用前会重新同步客户端与服务端的任务书内容指纹，服务器再次验证 FTBQ TeamData 编辑权限、字段、对象和物品 ID，再以可回滚批次执行。FTBQ 自带的 `PersistedData` 会在整本同步重建界面时恢复章节、缩放、滚动位置和多选任务，面板展开状态也会保留。工作台同步支持章节、任务、条件、奖励、章节组、奖励表、删除操作和当前整合包加载的自定义类型，并以原始 SNBT 保留未知字段；游戏命令仍未开放。服务器事务、Studio 结果回报和断线后的待处理工作台修改均可安全重试。

已通过 Java 17 干净构建和 Forge 开发客户端主菜单启动烟测。服务端权限、真实世界写入、失败回滚与撤销仍必须先在备份后的测试世界中交互验证，再用于正式任务书。
