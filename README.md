AutoFTBQ Studio 是面向 FTB Quests 的离线编辑器与 AI Agent 工作台。它直接读取和尽量无损地写回任务书 SNBT，让用户能在进入 Minecraft 前查看、修改、检查并由 Agent 逐步完善任务书。

项目正在增加“FTBQ 原生编辑器前端 + Studio Agent 后端”模式。首个适配位于 `game-mod`，面向 Minecraft 1.20.1 Forge：Agent 作为可折叠右侧面板直接嵌入 FTBQ 编辑模式。展开面板后可按住 `Alt` 左键点击任务或章节，将它们加入独立的 Agent 上下文；再次点击可取消，选区会在原生画布和章节列表中高亮。游戏和 Studio 共享持久化项目、聊天、工作记录与任务书快照；玩家可以在 FTBQ 原生界面编辑，也可以把实时任务书载入 Studio 工作台后无损同步回游戏。Agent 修改经过权限、ID、结构、revision 和选区范围检查后由游戏服务器自动以原子事务应用，不再等待人工批准，并保留可撤回快照。应用后由 FTBQ 自身恢复章节、缩放、滚动和选区，提交、结果回报及 Studio 重启后的待处理事务均支持幂等恢复。

游戏内的明确编辑要求本身就是执行授权，不需要再发送“确认”或“开始”。请求提交前会自动等待客户端与服务器任务书 revision 一致；模型完成核对但没有生成事务时，Studio 会自动续跑同一请求并直接准备可撤回修改。

> 当前处于 Alpha 开发阶段。稳定版 1.x 仍在 [AutoFTBQ](https://github.com/Bluelgin/AutoFTBQ) 仓库维护；请先备份整合包和任务书后再测试 v2。

游戏内 Mod 的安装、协议和真实世界验收分别见 [`game-mod/README.md`](game-mod/README.md)、[`docs/GAME_BRIDGE.md`](docs/GAME_BRIDGE.md) 和 [`docs/GAME_ACCEPTANCE.md`](docs/GAME_ACCEPTANCE.md)。

## 目前能力

- 后台扫描整合包并预热任务书使用的图标、配方、主题形状和安全可枚举的注册表 ID；扫描期间可随时停止，同一整合包未变化时直接恢复持久化资源索引。画布使用有界内存缓存，磁盘图标缓存每 30 分钟维护一次，普通方块模型会生成等距立体缩略图，多层物品贴图会自动合成。
- 任务图标可通过缩略图网格搜索选择；窗口只分批后台准备当前可见图标，也可一键使用完成条件物品或清除自定义图标。
- 离线查看与编辑章节、任务、全部官方任务条件和奖励、章节图片、任务跳转、章节组、奖励表、全局配置及原生多语言文件。
- 画布可向四个方向动态扩展，并支持平移、缩放、框选、多选、复制、删除、跨章节移动与依赖连线；支持官方曲线控制点和隐藏连线设置。
- 保留软件不认识的附加模组字段和未来版本字段，保存前建立备份，并提供撤销、重做及全任务书结构检查。
- Agent 按需查询真实 ID、配方和统一 Schema，再执行小步修改；每轮修改自动校验，可在界面预览后整体保留或撤销。
- Agent 会先建立可检查的执行计划，再按章节、任务数量、任务类型、前置关系、分层布局和结构错误逐项验收；右侧实时显示当前阶段、实际操作和安全检查点，技术行动记录默认折叠。
- Agent 默认使用精简工具集和较低推理强度；若自动验收未通过，修复阶段会临时升级到完整工具集与中等推理，完成后恢复用户配置。
- Agent 只会搜索通过模型、贴图和游戏内来源检查的安全物品；任务条件、奖励、图标和复制操作还会在工具层二次校验，无法确认或疑似开发中的 ID 会被拒绝。实体、维度、群系等注册表 ID 同样会校验；猜中但本轮未查询的安全 ID 允许使用，并显示黄色来源提醒。
- 每次有效修改都会先通过本地结构检查再形成安全检查点。参数或 Schema 错误只撤销当前工具；API 中断会保留此前成果，用户可继续执行、只撤销上一步或撤销本轮全部修改。
- 输入 `/` 可选择生成、改进、检查、补全、重排、连线、润色和解释模式；普通自然语言仍会自动识别意图。
- 按住 `Alt` 点击任务节点或章节可加入 Agent 上下文。选定范围后，软件会在工具层阻止 Agent 修改范围外的现有内容；再次点击可取消，输入区也可一键清除。
- 自动保存当前任务书草稿、Agent 对话与上下文、行动记录、当前选择、画布视图和未发送的输入，重启后继续上次工作区。
- 普通 v2 项目可导出为 FTB Quests SNBT；打开真实任务书时可直接安全写回原目录。
- 游戏连接后可点击“在工作台编辑游戏任务书”，编辑完整章节、任务、条件、奖励、章节组、奖励表和未知原始字段，再点击“同步到游戏”；游戏端会自动应用并提供撤回。
- 游戏与 Studio 使用稳定项目身份和 SQLite 事件时间线。重启或断线重连后会恢复聊天、工作记录、实时任务书镜像及尚未完成的工作台同步事务。

依赖游戏代码的动态材质和模组自定义渲染器无法在 Minecraft 外完整复现。Studio 会依次尝试静态模型、同 ID 代表贴图和刷怪蛋代表图标；仍无法解析时会显示 `?` 并说明原因，对应模型和 SNBT 数据不会丢失。

自动恢复文件保存在软件目录的 `.autoftbq_workspace` 中，只用于恢复编辑器内尚未保存的内容，不会自动写入游戏。打开真实任务书后，仍需点击“保存”才会写回 FTB Quests 目录。

## 运行

需要 Python 3.11 或更高版本。建议先创建独立虚拟环境：

```powershell
python -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install -r requirements-v2.txt
python v2_main.py
```

也可双击 `start_v2.bat`。Agent 读取软件目录中的 `config.json`，API Key 不会写入任务书项目。

## 打包

双击 `build_v2_exe.bat`，或运行：

```powershell
python -m PyInstaller --clean AutoFTBQ-v2.spec
```

Studio 使用独立的打包配置，生成 `dist/AutoFTBQ-Studio/AutoFTBQ-Studio.exe`，不会覆盖 v1 的源码或 `AutoFTBQ.spec`。发布和移动时必须保留整个 `AutoFTBQ-Studio` 目录；目录构建避免 Qt DLL 被单文件临时解包或外部 ICU 环境污染，并具有更快的启动速度。可运行 `AutoFTBQ-Studio.exe --smoke-test` 执行无界面的启动与本地桥接自检。

## 测试

```powershell
python -m unittest discover -s tests -p "test*.py"
```

每次推送和 Pull Request 都会在 GitHub Actions 中自动运行测试。测试不会调用真实付费 API。

## 项目结构

- `autoftbq_v2/agent_core`：Agent 计划、工具调用、范围控制、检查点和会话运行。
- `autoftbq_v2/editor`：任务画布、属性编辑、连接控制和物品选择器。
- `autoftbq_v2/ftb`：FTB Quests 数据模型、校验、读取和写回。
- `autoftbq_v2/infrastructure`：整合包扫描、AI 配置、日志和工作区恢复。
- 根目录兼容模块：复用自 v1 的扫描、SNBT 与 AI 客户端能力，后续会逐步收进 v2 包内。

## 安全说明

### 游戏内自由手绘布局（Mod alpha.15）

在 Studio 的 AI 设置中为已确认支持图片输入的模型启用“图片能力”，重启后端与游戏，在 FTBQ Agent 点击“布局画板”。自由画笔、橡皮、文字标注、撤销重做、缩放平移均可用；填写章节内容要求，选择外形优先或节点优先，预览后按图生成。原始 PNG 直接交给多模态模型，不先识别成规则节点；模型仍通过受校验的工具创建任务，不直接编写 SNBT。

第一版仅生成一个新章节，保留已有章节。未启用图片能力或旧后端会明确拒绝，不降级成纯文本。图片能力是用户配置声明，连接测试不证明模型理解图片的质量。画板草稿在本次游戏进程内保留，退出游戏后不保留；复杂草图的识别质量需要实际模型测试。支持已有章节截图编辑属于后续方向。

API Key 只保存在本机配置中，不应提交到 Git。保存真实任务书前软件会创建备份，但 Alpha 期间仍建议保留整合包的独立备份。
